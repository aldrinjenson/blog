Street View to Video - Virtual Road Trip Generator 🎬

Links

  • GitHub Repo
  • Live Demo

Project Abstract

Ever wanted to take a virtual walk through the streets of Rome, Paris, or Tokyo without leaving your desk? This project does exactly that! Enter a start and end location, and the app creates a smooth video by stitching together Google Street View images along the entire path - like a cinematic road trip generated from Street View data.

Tech Stack

  • Python - Core logic
  • Streamlit - Web UI framework (love how fast you can build things with this!)
  • Google APIs - Geocoding, Directions, Street View Static, and Places API
  • FFmpeg - Video generation and audio mixing
  • MoviePy - Video processing

Features

The app turned out quite feature-rich:

  • 🗺️ Interactive Map Preview - See your route before generating
  • 📍 Place Autocomplete - Smart search powered by Google Places
  • 🧭 Direction Compass - Shows heading direction overlaid on each frame
  • 🎵 Background Music - Add ambient music to your videos
  • 🎚️ Customizable - Adjust FPS, capture interval, FOV, camera pitch
  • 💰 Cost Tracking - Know your API costs upfront (important since Street View API isn’t free!)
  • 📁 Project Gallery - View and manage all your generated videos
  • 🌍 20+ Preset Routes - Famous walking tours worldwide (Times Square to Central Park, Colosseum to Trevi Fountain, etc.)

How it came to be

I was watching some “walking tour” videos on YouTube - you know, those relaxing videos where someone just walks through a city with a camera? They’re oddly satisfying to watch. Then I thought - Google Street View has imagery of almost every street in major cities. What if I could stitch those images together into a video?

The core idea was simple:

  1. Get a route between two points using Google Directions API
  2. Sample points along that route at regular intervals
  3. Fetch Street View images at each point, oriented in the direction of travel
  4. Stitch them into a video

The execution involved some interesting challenges:

  • Calculating heading - Each frame needs to “look” in the right direction. Had to calculate bearing between consecutive points using spherical trigonometry.
  • Smooth transitions - Too few frames = choppy video. Too many = expensive API costs. Found 10-15 meter intervals work well.
  • Street View coverage gaps - Not every location has imagery. Had to handle this gracefully.
  • Cost optimization - Street View API costs $7 per 1000 requests. Added cost estimation before generation so users know what they’re getting into.

Thoughts

The project scratched a creative itch. There’s something magical about virtually “driving” through streets you’ve never visited. I’ve generated videos of routes in cities I’ve always wanted to visit - the walk from Colosseum to Trevi Fountain in Rome, strolling down Las Ramblas in Barcelona, or crossing the East Side Gallery to Alexanderplatz in Berlin.

Some interesting observations:

  • Street View coverage is incredibly comprehensive in touristy areas, but gets sparse quickly in residential zones
  • The video quality is limited to 640x640 (Street View API limit), but it’s good enough for the vibe
  • Adding background music really transforms the experience - a calm ambient track makes it feel like a proper travel video

The Streamlit deployment was smooth. The app runs on Streamlit Cloud with just a Google API key secret. Though videos are temporary there - gotta download them before they disappear!

This was a fun weekend project that actually turned out useful. Sometimes the simple ideas are the best ones. 🙂
